## 三、面试高频追问 + 参考答案（最重要）

### Q1：为什么评分不让 LLM 直接打，要用确定性规则？

**答**：LLM 打分是黑盒——同样输入每次结果可能不同，无法回归、无法追责。我的设计是「分工」：LLM 只负责提取**事实字段**（客户类型、规模信号、联系方式这类枚举/布尔值），加减分走**固定规则**。这样评分稳定可回归，改权重就能调优，而且每一分都有 `reason` 可解释。这是整个系统可靠性的核心。

### Q2：n8n 和直接写代码有什么区别？为什么用 n8n？

**答**：n8n 负责**流程编排**（把调 AI、搜数据、存文件串成流水线），代码节点做**复杂逻辑**（评分引擎）。好处是改流程不用重写代码、可视化易维护。但纯 n8n 拖拽搞不定复杂逻辑，所以评分引擎单独写成 Node.js 模块，内联进代码节点——「编排用工具，逻辑用代码」。

### Q3：你遇到的最大技术难点？怎么解决的？

**答**（挑 1-2 个讲，真实案例）：
- **DeepSeek 401 授权失败**：定位发现是 baseUrl 还指向 OpenAI，用 DeepSeek 的 Key 打 OpenAI 的门。解决：配置改 baseUrl+model，重新生成工作流。
- **n8n 配对链断裂**：节点做了去重+一对多展开后，下游用 `.item` 表达式报错。解决：改用 `.first()`/按索引对齐，不依赖配对链。
- **文件访问被拒**：n8n 2.x 默认禁文件节点访问任意路径，加 `N8N_RESTRICT_FILE_ACCESS_TO` 白名单解决。

### Q4：怎么保证「通用」——换行业不动代码？

**答**：把「会变的」（产品、国家、客户类型、评分权重）全放 `config/*.json`，把「不变的」（评分逻辑、流程）放代码。换行业 = 新建一个 ICP 配置文件 + 重新生成工作流，不改一行代码。这是「配置与代码分离」的落地。

### Q5：AI 项目里，Prompt 工程你具体做了什么？

**答**：四个 Prompt 各司其职——系统提示词定「人设和规则」，任务提示词定「干什么」，强制**严格 JSON 输出** + **枚举封闭**（AI 只能选固定值，防止乱编），并强调「宁缺勿猜」（拿不准输出 null 而非编造）。这让 AI 输出能稳定进流水线。
