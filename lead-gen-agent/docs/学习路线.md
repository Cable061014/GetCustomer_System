## 阶段 4：调用 LLM API（1 周，核心中的核心）

**目标**：理解「AI 应用的本质 = 发一段话给模型，拿回结果」。

### 概念

- **API**：程序之间「打电话」的接口。你发请求，它返回结果。
- **LLM**：大语言模型（DeepSeek、GPT 等）。
- **调用流程**：你的代码 → HTTP 请求（带 Key + 消息）→ 模型 → 返回 JSON。

### 必做练习（这个练习做完，你就懂 AI 应用了）

写一个 15 行的脚本，发一句话给 DeepSeek，打印回复：

```javascript
// 文件：test_llm.js
const key = '你的DeepSeek Key';
async function ask(prompt) {
  const res = await fetch('https://api.deepseek.com/v1/chat/completions', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${key}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      model: 'deepseek-chat',
      messages: [{ role: 'user', content: prompt }],
    }),
  });
  const data = await res.json();
  console.log(data.choices[0].message.content);
}
ask('用一句话解释什么是路由器');
```

**跑通后你会明白**：项目里「生成关键词、分析公司、写开发信、判意向」四个功能，本质都是这段代码的变体——只是 `prompt` 和 `messages` 不同。

## 阶段 5：Prompt 工程（1 周，最值钱的技能）

**目标**：学会「让 AI 稳定输出你要的东西」。

### 核心技巧（本项目已经用上的）

1. **系统提示词**：定 AI 的「人设和规则」（见 `prompts/system_prompt.md`）
2. **任务提示词**：告诉 AI 具体干什么（见 `prompts/02_company_analyst.md`）
3. **严格 JSON 输出**：让 AI 输出机器能读的格式，不是人话
4. **枚举封闭**：限定 AI 只能选固定几个值（如 buyerType 只能是 distributor/wholesaler/...），防止它乱编
5. **宁缺勿猜**：告诉 AI 拿不准就输出 null，别瞎填

### 必做练习

读项目里 `prompts/` 文件夹的 4 个文件，逐个回答：
- 这个 Prompt 的「系统提示词」定了什么规则？
- 它的「输出格式」为什么必须是 JSON？
- 它的「枚举」为什么封闭？

**验收**：能自己写一个 Prompt，让 AI 输出一个固定格式的 JSON（比如「判断一封邮件是客户还是垃圾」）。

## 阶段 8：工程思维（1 周，决定你能走多远）

**目标**：理解「为什么这个项目这么设计」。

### 3 个核心思想（比技术更重要）

1. **配置与代码分离**：业务规则放 `config/*.json`，逻辑放 `scripts/*.js`。改业务不改代码 → 通用。
2. **确定性 vs 概率**：AI 只提取事实（枚举/布尔），打分用确定性规则。→ 稳定可解释。
3. **测试驱动**：改了东西跑测试，确保没改坏。→ 可维护。

**练习**：回答这三个问题——
- 如果把「评分」也交给 AI 直接打分，会出什么问题？
- 为什么换行业只改 ICP 文件，不用改代码？
- 为什么要有 13 条单测？
